## Unix

UNIX - это семейство переносимых, многозадачных и многопользовательских операционных систем, основанных на идеях оригинального проекта

- это проприетарная (закрытая) система с закрытым исходным кодом, которая исторически использовалась в основном на серверах

## Linux

Linux — это семейство свободных, открытых операционных систем, основанных на ядре Linux. Его создал Линус Торвальдс в 1991 году как бесплатную альтернативу другим системам

Linux не является версией или наследником UNIX в строгом смысле: его разработчики сознательно создали систему, вдохновлённую философией UNIX, но с нуля написали собственную кодовую базу

## Posix

POSIX - это набор стандартов, который описывает, каким должен быть интерфейс операционной системы.

Главная цель POSIX — обеспечить переносимость программного кода. Если программа написана с использованием только тех функций и вызовов, которые определены в POSIX, её исходный код можно скомпилировать и запустить на любой другой POSIX-совместимой системе с минимальными изменениями или вообще без них

## Файловая система

Файловая система - это способ организации, хранения, именования и доступа к файлам.

## Интерпретатор

Интерпретатор — это программа, которая читает ваш код и сразу его выполняет, строчка за строчкой

## Компилятор

Компилятор — это программа, которая переводит исходный код в машинный код целиком, до того как программа будет запущена

## Консоль && терминал && оболочка

Терминал — это устройство (или программа) для ввода и вывода текста. 

Консоль — это физическая панель управления или главный системный терминал. 

Shell (оболочка) — это та самая программа-интерпретатор, которая работает внутри них

Bash — это конкретная программа, которая является одним из самых популярных Shell'ов в мире

### Порядок работы

1. Вы открываете Терминал

2. Внутри этого терминала автоматически запускается Оболочка (Shell), например bash — тот самый интерпретатор

3. Вы пишете команду: ls -l и нажимаете Enter

4. Терминал передает эту текстовую строку оболочке. (Терминал не понимает, что такое ls, он просто передает текст)

5. Оболочка (интерпретатор) читает строку, понимает, что это команда, и делает системный вызов к Ядру (просит его вывести список файлов)

6. Ядро выполняет работу

7. Результат (список файлов) отправляется обратно через оболочку в терминал

8. Терминал отображает этот текст на вашем экране

## История Linux && Unix

Лицензия BSD — это одна из самых свободных открытых лицензий

### Unix
1969: Первая версия Unix, написанная на ассемблере

1971: Выпуск Unix V1 и первого руководства по системе

1973: Поворотный момент — Unix переписывается на только что созданный язык C. Это делает систему переносимой на другие компьютеры, что и обеспечило ей будущее

1974: Публикация статьи о Unix в журнале ACM, после чего систему начали активно распространять в университетах

1975: Выпуск Unix V6, который стал широко доступной «исследовательской» версией

1979: Выпуск Unix V7, который считается последней «настоящей» Unix от Bell Labs и прямым предком большинства современных коммерческих Unix-систем

### Linux
В 1991 году финский студент Линус Торвальдс начал работу над ядром в качестве хобби-проекта. Он был вдохновлен системой Minix (учебной Unix-подобной ОС) и стремился создать что-то совместимое с POSIX. 25 августа 1991 года он публично объявил о своем проекте в новостной группе

## Файловая система

В мире *NIX действует главное правило: «Всё есть файл». Диски, папки, процессы, устройства - для ядра всё это выглядит как файлы

### Корень / (inode=2)

Это самая вершина (синяя папка). Отсюда растет всё остальное

### Стандартные папки

/home — здесь лежат папки пользователей (например, serge)

/usr/bin — здесь лежат исполняемые файлы программ (те самые ls, bash, sort, grep, которые мы обсуждали)

/var, /tmp — для временных файлов и изменяемых данных

/dev (зеленая папка) — здесь лежат файлы устройств (диски, мыши)

/proc (зеленая папка) — виртуальная файловая система (об этом ниже)

/export — обратите внимание на иконку диска. Это точка монтирования. Сюда подключен отдельный физический диск или раздел

### Имена файлов

не могут в себе содержать символ "/", а также спецсимвол обрезки "\0"

### Права доступа
Три типа прав: r (чтение), w (запись), x (выполнение).

Три категории пользователей: u (владелец), g (группа), o (остальные).

Команды: chmod (смена прав, например chmod +x file или chmod 755 file), chown (смена владельца)

#### SUID && SGlD

Задать сразу SUID && SGlD
```
chmod a+s file1
```

Задать сразу SUID
```
chmod u+s file1
```

Задать сразу SGlD
```
chmod g+s file1
```

```
chmod 6777 file1

-rwsrwsrwx     2 s558473 studs   12  8 окт.  17:57 file1
```

```
chmod 6000 file1

---S--S---     2 s558473 studs   12  8 окт.  17:57 file1
```

Если права на исполнения есть - s; Если права нет - то S (выше пример)

#### Stiсky-бит

Если на папке установлен Sticky bit. Теперь удалить файл из этой папки может только тот, кто его создал (владелец файла), либо владелец самой папки, либо суперпользователь root

```
ls -ld /tmp
drwxrwxrwt 10 root root 4096 Oct 24 10:00 /tmp
```

Если запрещено исполнение для других
```
drwxr-x--T     5 s558473 studs    8  8 окт.  17:15 lab0
```

### Inode

Inode (индексный дескриптор) — это невидимая для пользователя структура данных на диске, которая хранит всю информацию о файле, кроме его имени. В inode записано: кто владелец файла, какие у него права доступа, какого он размера, и где именно на жестком диске лежат его данные

Inode совпадают:
- у жестких ссылок (указывают на один адрес памяти)
- в разных файловых системах могут совпадать inode

### Жесткие ссылки

ln <файл> <название жесткой ссылки>
```bash
ln file1 link 
```

Жесткие ссылки нельзя делать на папки (чтобы не было циклов) и нельзя делать между разными дисками (так как inode уникален только внутри одного раздела)

### Символические ссылки

Симлинк — это отдельный файл со своим собственным inode, внутри которого просто записан текстовый путь к другому файлу. Если вы удалите оригинал, симлинк останется, но будет «битым» (не будет работать)

## Дескрипторы

Файловый дескриптор - это просто число (целое), которое ядро выдает процессу, когда тот открывает файл (или сокет, или устройство), чтобы процесс мог потом работать с этим файлом, не зная его реальных адресов на диске

Зарезервированные:

- 0 - stdin
- 1 - stdout
- 2 - stderr

## Escape-последовательность

Это комбинация символов, которая говорит программе (или терминалу): «Не воспринимай следующие за мной символы буквально. Я даю тебе особую команду»

- \t - табуляция
- \n - перевод строки
- \b - удаления
- \r - возврат консоли

Еще из интересных:
- \e[m34 - смена цвета

## Временные ветки

Linux/Unix у каждого файла (точнее, в его inode) есть три временные метки:

atime (Access time) — время последнего чтения файла (например, когда вы сделали cat).

mtime (Modification time) — время последнего изменения содержимого (когда вы дописали текст).

ctime (Change time) — время последнего изменения метаданных (inode). Оно меняется, когда вы меняете права (chmod), владельца (chown) или... когда срабатывает touch.

## Команды
### ls

Флаги

- a - показать скрытые
- A - показать скрытые без . и ..
- l - длинный формат
- 1 - один файл на строку
- h - Используется только с -l. Превращает размеры из байтов в K, M, G (например, 4.0K вместо 4096)
- C / -x: Вывод в несколько колонок (по умолчанию при выводе в терминал). -x сортирует по строкам, а -C — по колонкам.

- t: Сортировка по времени изменения (самые новые сверху).
- S: Сортировка по размеру (самые большие сверху).
- r: Реверс (обратный порядок). Часто используется с -t (ls -ltr — самые старые сверху, идеально для чтения логов).
- v:  «Натуральная» сортировка (файлы file1, file2, file10 будут идти по порядку, а не file1, file10, file2, как при обычной алфавитной).

- i: Показывает номер inode! (Помните, мы обсуждали, что это паспорт файла).
- s: Показывает размер в блоках, занятых на диске.
- F: Добавляет спецсимволы в конец имени: / (папка), * (исполняемый файл), @ (симлинк), = (сокет).
- d: Показывает информацию о самой папке, а не о её содержимом. (Полезно с -l, чтобы узнать права на каталог).

- L: Показывает данные файла, на который указывает ссылка.
- P: Показывает данные самой ссылки (по умолчанию).
- H: Следует по ссылкам только в аргументах командной строки.

### pwd

- L: Покажет вам путь так, как вы его набирали: /home/studs/mylink
- P: Покажет реальный, физический путь на диске, «развернув» все ярлыки: /home/studs/realdir

### wc

- l (lines): Считает количество символов перевода строки (\n). Важно: если текст не заканчивается на Enter, последняя строка не засчитается!
- w (words): Считает последовательности символов, разделенные пробелами, табами или переводами строк. Обратите внимание: FreeBSD! считается за одно слово, потому что ! не является пробелом.
- c (bytes): Считает байты. Это физический размер файла на диске.
- m (characters): Считает символы (учитывая кодировку UTF-8).
- L (Longest line): Это фишка FreeBSD (в Linux она тоже есть, но появилась позже). Показывает длину самой длинной строки в файле (в байтах или символах, если добавить -m).


### head

-n count: Вывести указанное количество строк
Пример: head -n 3 file.txt (покажет 3 строки)

-c bytes: Вывести указанное количество байт (а не строк!)
Пример: head -c 50 file.txt (покажет первые 50 байт, даже если это обрубит слово посередине)

- q (quiet): Отключает эти заголовки. Выводит просто подряд содержимое файлов (как cat).

- v (verbose): Наоборот, принудительно включает заголовки, даже если указан только один файл

### tail

- n number: Количество строк с конца.

- c number: Количество байт с конца.

Знак + (плюс) — Очень важная фишка из man! Если вы напишете tail -n +5 file.txt, это будет означать: «Начни вывод с 5-й строки и иди до конца файла» (то есть выведет всё, кроме первых 4 строк).

- r: Вывести файл в обратном порядке (с конца в начало).

- q (quiet): Отключает эти заголовки. Выводит просто подряд содержимое файлов (как cat).

- v (verbose): Наоборот, принудительно включает заголовки, даже если указан только один файл

- f (follow): Программа не завершается, когда доходит до конца файла. Она «зависает» и ждет, пока в файл допишут новые данные. Как только данные появляются — tail их сразу выводит

- F (FreeBSD extension): Это -f на стероидах. В man написано: "check to see if the file being followed has been renamed or rotated... detects that the filename being read from has a new inode number"

### mkdir

- p (Parents) — Самый важный флаг! Позволяет создавать целую цепочку вложенных папок, даже если родительских папок не существует.

Пример: mkdir -p cow/horse/monkey (создаст сразу три папки друг в друге).

Бонус: Если папка уже существует, -p не выдаст ошибку, а просто молча продолжит работу. Без -p система выдаст File exists.

- m (mode) — Задать точные права на лету.

- v (verbose) — Показывать, что именно создается (полезно для скриптов).

### rmdir

- p — Удаляет цепочку папок. Например, если у вас есть cow/horse/monkey, и папка monkey пуста, команда rmdir -p cow/horse/monkey удалит monkey, затем horse, затем cow (если они тоже пустые). Остановится на первой непустой папке.

### rm

- r / -R (Recursive) — Рекурсивное удаление. Позволяет удалять папки вместе со всем содержимым.

Пример: rm -r my_dir (удалит папку и всё внутри).

- f (Force) — Игнорировать ошибки и не задавать вопросов. Если файла нет — молчать. Если нет прав на запись — попытаться удалить всё равно.

Пример: rm -rf my_dir — легендарная и самая страшная команда. Удаляет всё без вопросов и предупреждений.

- i (Interactive) — Спрашивать подтверждение перед удалением каждого файла (страховка от случайного нажатия Enter).

- d — Удалить пустую папку (аналог rmdir).

### echo

- n: Не выводить символ новой строки в конце

### cat

- n (number) — Нумерует все строки вывода.
- b (number non-blank) — Нумерует только непустые строки. (Если в файле много пустых строк, -b сделает вывод гораздо чище).
- s (squeeze) — Сжимает несколько пустых строк в одну. Очень полезно, если кто-то налепил в конфиг 10 пустых строк подряд.

- v — Показывает непечатаемые символы.
- t — Показывает табуляцию как ^I.
- e — Показывает конец каждой строки значком $

### touch

Без флагов: создает пустой файл или ставит текущее время.

- a и -m: меняют только время доступа или только время модификации.

- c: не создавать файл, если его нет.

- t и -d: установить конкретное время (в POSIX-формате или в удобном человекочитаемом формате ISO).

- r: скопировать время с другого файла-эталона.

- A: прибавить или отнять заданное количество времени от текущих меток.

- h: изменить время самой символической ссылки, а не файла, на который она указывает».

### cp

- R (Recursive): Копировать папку со всем содержимым. Без нее скопировать папку нельзя.
- H (Follow command-line symlinks): Если в аргументах есть симлинк, скопировать файл, на который он указывает. (Ссылки внутри папки не разыменовываются).
- L (Follow all symlinks): Разменовывать все симлинки (копировать реальные файлы, на которые они указывают).
- P (No follow): Копировать сами симлинки как ссылки. (Это поведение по умолчанию для -R в FreeBSD).
- i (Interactive): Спрашивать подтверждение перед перезаписью каждого файла.
- f (Force): Удалить существующий файл и скопировать новый без вопросов (даже если нет прав на запись в файл, но есть права на папку).
- n (No clobber): Никогда не перезаписывать существующие файлы. (Очень полезно, чтобы случайно не затереть данные).
- p (Preserve): Сохранить метаданные оригинала: время изменения/доступа (mtime/atime), права (rwx), владельца (UID/GID) и ACL.
- a (Archive): Режим архивации. Это то же самое, что -RpP. Сохраняет всё, включая симлинки как симлинки.
- N: Используется только с -p. Запрещает копировать системные флаги файлов (file flags) FreeBSD.
- l (Link): Создать жесткие ссылки (hard links) на файлы вместо копирования.
- s (Symbolic): Создать символические ссылки (symlinks) на файлы вместо копирования.
- v (Verbose): Показывать, какие файлы копируются.
- x (No cross mount): При копировании папки не переходить на другие смонтированные диски (например, если внутри папки примонтирована флешка, ее содержимое не скопируется).

### mv

- f (Force): Перезаписать без вопросов.
- i (Interactive): Спросить подтверждение (y/n), если файл существует.
- n (No clobber): Не перезаписывать существующие файлы.


- h: Очень хитрый флаг для работы с символическими ссылками. Если target — это симлинк, указывающий на папку, по умолчанию mv зайдет внутрь этой папки и положит файл туда. Флаг -h заставляет mv не переходить по ссылке, а переименовать файл в имя самой ссылки (заменив её).
- v (Verbose): Показывать, что было перемещено.

### ln

- s: Создать символическую (мягкую) ссылку.

- f (Force): Если целевой файл уже существует, удалить его без вопросов (перезаписать).

- i (Interactive): Спросить подтверждение перед удалением существующего целевого файла.

- n / -h: Не следовать по символическим ссылкам в целевом аргументе

- v (Verbose): Показывать, какие ссылки создаются.
 
- w: Предупреждать, если файл-источник не существует (по умолчанию создаст «битую» ссылку молча).


### sort

- n (Numeric): Сортировать как числа (арифметически).

Пример: Если у вас числа 2 и 10, без -n файл отсортируется как 10, 2 (потому что символ '1' идет раньше '2'). С флагом -n будет правильно: 2, 10.

- h (Human-numeric): Гениальная фишка для сисадминов. Сортирует размеры, учитывая суффиксы (K, M, G).

Пример: Если вы сделали ls -lh или du -sh и хотите отсортировать по размеру, используйте sort -h. Он поймет, что 1G больше, чем 500K.

- V (Version-sort): Сортирует номера версий правильно. sort -V поставит v1.9 перед v1.10 (а обычный sort поставил бы v1.10 первым, так как '1' меньше '9').
- R (Random): Перемешать строки в случайном порядке (отличный способ сделать пароль или выбрать случайную строку).
- M (Month): Сортирует по названиям месяцев (Jan, Feb, Mar...), даже если они идут не по алфавиту.

- t (Field separator): Указать разделитель (по умолчанию это пробел или табуляция).
- k (Key): Указать, по какому полю сортировать.

Пример: sort -t ':' -k 3 -n /etc/passwd (разделитель :, сортировать по 3-му полю, как числа).

- o: безопасный перезапись в тот же файл sort file1 -o > file1

- c (Check): Не сортирует, а просто проверяет, отсортирован ли файл. Если нет — выдает ошибку и код возврата 1. (Очень полезно в скриптах).
- m (Merge): Сливает несколько уже отсортированных файлов в один. Работает невероятно быстро, так как не сортирует заново, а просто как колода карт вставляет строки в нужном порядке.
- u (Unique): Удаляет дубликаты строк (оставляет только уникальные).

### grep

- i (ignore-case): Игнорировать регистр (найдет и Error, и error, и ERROR).
- w (word-regexp): Искать только целые слова. (Если искать cat, он не найдет concatenate).
- v (invert-match): Инвертировать поиск. Показать все строки, которые НЕ содержат шаблон. (Очень полезно для фильтрации логов).
- c (count): Вместо самих строк вывести только их количество.
- l (files-with-matches): Вывести только имена файлов, в которых есть совпадения (а не сами строки).
- L: Наоборот, вывести имена файлов, где совпадений нет.
- n (line-number): Показать номер строки перед каждой найденной строкой.
- o (only-matching): Вывести только ту часть строки, которая совпала с шаблоном (а не всю строку целиком).

- r / -R (recursive): Искать во всех файлах внутри папки и её подпапок.

- A num (After): Показать num строк после совпадения.
- B num (Before): Показать num строк до совпадения.
- C num (Context): Показать num строк до и после (окружение).
